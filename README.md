# bugDan

Исправление багов из TFS с помощью Claude: `bug_fixer.fix_bug` читает карточку, создает ветку от нужной
базовой, просит Claude внести исправление, пушит ветку и создает черновик pull request.

## Запуск по тегу AIFix

`server.py` принимает события service hook TFS и запускает исправление, когда на карточку бага ставят тег
**AIFix**. Сам тег сервер не проверяет: это делает фильтр подписки в TFS, а сервер лишь убеждается,
что в событии появился новый тег. Удаление тега и изменения карточки без новых тегов обработку не запускают. Чтобы запустить
обработку повторно, тег снимают и ставят снова. Запуски идут по очереди, по одному; лог каждого запуска
пишется в `logs/<номер>-<время>.log`, общий лог сервера - в `logs/server.log`.

### Запуск сервера

```
set TFS_PAT=<PAT с правами Work Items (read) и Code (read & write)>
set BUGDAN_HOOK_USER=tfs
set BUGDAN_HOOK_PASSWORD=<пароль для вебхука>
python server.py --repo-path D:\Projects\master\RX
```

Сервер вызывает `bug_fixer.fix_bug(<ссылка на карточку>, <repo-path>)`. Ссылка на карточку имеет вид `.../_workitems/edit/<номер>`. Префикс ветки берется из Area
карточки - уровень сразу под проектом (`SmartInstruments\Vega` → `vega/...`). Если Area - корень проекта,
префикс берется из базовой ветки (`vega/43375-x` → `vega/...`), а для `master` - `bugfix/`.

Параметры сервера: `--repo-path` (обязательный), `--verbose` (писать в лог и пропущенные события).
Модели Claude задаются константами `MODEL` и `SLUG_MODEL` в `bug_fixer.py`. Адрес и порт (`0.0.0.0:8080`), путь вебхука (`/propose-fix`), типы карточек (`Bug`)
и папка логов задаются константами `HOST`, `PORT`, `HOOK_PATH`, `WORK_ITEM_TYPES`, `LOG_DIR` в начале `server.py`.
Проверка работы: `GET http://<хост>:8080/health`.

Для постоянной работы сервер удобно оформить службой Windows, например через NSSM. Служба должна работать
от учетной записи, у которой в PATH есть `claude` (или задан `CLAUDE_BIN`), выполнен вход в Claude
и настроен доступ git к репозиторию. Входящие подключения на порт сервера должны быть разрешены
в брандмауэре для сервера TFS.

### Подписка в TFS

Project Settings → Service hooks → Create subscription → **Web Hooks**:

- событие **Work item updated**, Area path `SmartInstruments\Vega`, тип карточки **Bug**,
  тег **AIFix**, поле **Tags**;
- URL: `http://<хост>:8080/propose-fix`;
- Basic authentication: `BUGDAN_HOOK_USER` / `BUGDAN_HOOK_PASSWORD`;
- Resource details to send: **All**.

Кнопка **Test** в мастере отправляет тестовое событие; сервер ответит `ignored`, это нормально.

### Ограничения

- Срабатывает только изменение карточки. Если баг создан сразу с тегом AIFix (в том числе копированием),
  тег нужно снять и поставить снова.
- Очередь хранится в памяти: события, пришедшие до перезапуска сервера и еще не обработанные, теряются.
- Если ветка бага уже есть, исправление завершится с ошибкой, ничего не изменив (видно в логе запуска).
